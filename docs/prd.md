1. 登录页（login）
内容：

大标题：组织活力小测试

副标题：激活员工敬业度 提高组织活力 从调查开始

表单字段（每个字段占一行）：

您的姓名：输入框（文本）

您的电话：输入框（数字键盘）

您服务的公司全称：输入框（文本）

您的职位：输入框（文本）

公司总人数：输入框（数字键盘）

公司行业：下拉菜单（选择框），选项包括：制造业（工矿企业）、物业、物流、房地产、电商、教育培训、事业单位

提示文字：为生成的报表更符合您公司的现状，请认真思考后填写

按钮：【开始诊断】（点击后跳转到问卷页，并携带表单数据）

样式：

整体居中，上下左右边距一致。

标题字体稍大加粗，副标题较小灰色。

每个字段左侧标签右对齐，输入框占满剩余宽度（或使用微信原生样式）。

按钮圆角，主色调（如绿色或蓝色）。

交互：

表单需做简单非空校验（姓名、电话、公司全称必填）。

提交后保存表单数据到全局变量或本地存储，供后续页面使用。

2. 问卷页（survey）
结构：

显示两个部分：

一、个人活力（主动性/成长）：问题1~5

二、团队活力（协作/信任）：问题6~7

每个问题格式：

问题编号和标题，例如“1、每个员工都知道自己的工作目标与核心职责，且与组织目标一致。（目标与职责）”

下方5个选项水平排列，每个选项为“（5分）非常符合”到“（1分）非常不符合”，使用单选按钮。

页面底部固定一个【提交】按钮。

具体问题：

text
一、个人活力
1. 每个员工都知道自己的工作目标与核心职责，且与组织目标一致。（目标与职责）
2. 公司为我提供了完成工作所需的资源、工具和培训支持（工作支持与成长性）
3. 公司的薪酬福利、激励机制公平合理，能匹配大部分员工的付出与价值（激励机制）
4. 我的创新建议会被上级认真考虑（创造力激发）
5. 公司的激励机制让我愿意付出额外努力（结果导向）

二、团队活力
6. 团队成员能坦诚沟通分歧，无需顾虑（开放沟通）
7. 跨部门协作时，资源和支持能快速到位（高效协作）
选项统一：

（5分）非常符合

（4分）比较符合

（3分）一般

（2分）不太符合

（1分）非常不符合

样式：

每个部分标题加粗，字号略大。

问题卡片式设计，浅灰背景，圆角，内边距。

选项使用flex水平分布，每个选项包含radio和文字，适当间距。

底部按钮固定悬浮（或普通流式，但需确保滑动后可见）。

整个页面可上下滑动显示全部内容。

交互：

所有问题必须完成选择才能提交（提交时校验）。

点击提交后计算得分：个人活力得分 = 问题1~5的平均分；团队活力得分 = 问题6~7的平均分；组织活力得分 = (个人活力+团队活力)/2。得分保留一位小数。

跳转到报告页，并携带公司名称、得分数据。

3. 报告页（report）
内容：

显示文本：“从个人活力、团队活力、组织活力三个维度进行诊断”

显示公司名称（从登录页获取），格式：“某某 公司”

显示诊断得分：三个维度的得分分别展示，或一个总分？用户描述中只写了“诊断得分：”，但前面提到三个维度，建议展示三个分数，例如：

text
个人活力得分：4.2
团队活力得分：3.8
组织活力得分：4.0
或者简洁显示一个总分（如组织活力得分）。为符合描述，可显示“诊断得分：4.0”，并在下方用小字显示分项得分。根据用户给出的示例，后续建议页是根据整体情况，所以可能只需要一个总分。建议页面顶部显示总分，下方显示分项。

按钮：【生成诊断报告与建议】（点击跳转到建议页，并携带得分数据和公司信息）

样式：

得分数字放大加粗。

整体居中，简洁。

4. 建议页（advice）
内容：

根据诊断得分显示不同的报告内容。用户只提供了一个示例（“活力不足”情况）。为了演示，我们根据得分范围显示不同内容，但内容未全部提供，因此先实现示例内容，并在代码中注释可根据实际得分动态修改。

示例内容（得分较低时显示）：

text
▶活力不足
1. 结果简述
您的组织在基础运营中存在明显短板，员工主动性不足、协作效率低，需优先解决资源支持与目标共识问题，避免影响整体绩效。

2. 关键问题
- 🚫 资源支持缺失：工具/培训不足，工作推进受阻
- 🚫 目标共识破裂：个人与组织目标脱节，员工盲目干活
- 🚫 激励机制失效：付出与回报不匹配，积极性受挫

3. 优化建议
短期急救（1-2个月）
• 召开全员目标对齐会，明确各岗位核心职责
• 优先解决高频工作所需工具/权限问题
• 设立“月度优秀贡献奖”，快速激活积极性

中期巩固（3-6个月）
• 优化薪酬体系，增加绩效奖金占比
• 搭建跨部门协作平台，明确对接人
• 开展基础技能培训，弥补能力短板
如果得分中等或较高，可暂时显示“活力良好”或“活力优秀”的占位内容，后续替换。可以简单判断：若组织活力得分 < 3，显示上述示例；否则显示“活力良好，继续保持”等占位文本。

样式：

使用简洁列表，标题加粗，段落清晰。

关键问题用红色叉叉emoji。

优化建议分栏或列表。

交互：

无按钮，直接显示内容。

二、后台管理页面（web）
页面用途：显示用户提交的注册信息（登录页填写的内容），以及诊断日期。

页面内容：

标题：用户数据列表

表格，列包括：

序号

诊断日期（提交时的日期）

公司

诊断人（姓名）

职位

公司总人数

电话

下方可放置刷新按钮或说明。

样式：

使用简洁的HTML表格，白色背景，隔行变色，字体统一。

响应式或固定宽度。


样式与体验要求
整体风格简洁干练，无多余装饰。

字体使用系统默认，适当行高和边距。

按钮圆角，点击有反馈（如透明度变化）。

确保所有内容在手机屏幕内可滑动查看，不要出现内容被截断。

后台页面风格清爽，表格易读。
